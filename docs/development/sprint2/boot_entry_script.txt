######### TDC offset — validated sysfs approach ########
#
# Set TDCR before bringing up the mttcan interfaces.
# Value 0x800 is validated for the TJA1051T/3 (Adafruit CAN Pal).
# Must be applied while the interface is DOWN.
#
# This is handled automatically by scripts/activate_native_can.sh.
# See docs/assets/omnihand/omnihand_canfd_setup.md for the full context.

### set TDC offset:
```bash
echo "0x800" | sudo tee /sys/devices/platform/bus@0/c310000.mttcan/net/can0/tdc_offset
echo "0x800" | sudo tee /sys/devices/platform/bus@0/c320000.mttcan/net/can1/tdc_offset
```

### verify:
```bash
cat /sys/devices/platform/bus@0/c310000.mttcan/net/can0/tdc_offset
cat /sys/devices/platform/bus@0/c320000.mttcan/net/can1/tdc_offset
```

### bring up can0/can1 (right/left side bus):
```bash
cd ~/workspace/agx_arm_ros/scripts/ && sudo ./activate_native_can.sh
```

or manually (right side):
```bash
sudo ip link set can0 down
echo "0x800" | sudo tee /sys/devices/platform/bus@0/c310000.mttcan/net/can0/tdc_offset
sudo ip link set can0 type can bitrate 1000000 sample-point 0.8 \
    dbitrate 5000000 dsample-point 0.8 fd on restart-ms 100 one-shot on
sudo ip link set can0 name can_nero_right
sudo ip link set can_nero_right up
```

### verify OmniHand:
```bash
cd ~/workspace/agx_arm_ros/vendor/OmniHand-Pro-2025
PYTHONPATH=$PWD/build/agibot_hand_pkg \
LD_LIBRARY_PATH=$PWD/build/agibot_hand_pkg/agibot_hand:$LD_LIBRARY_PATH \
OMNIHAND_SOCKETCAN_IFACE=can_nero_right \
python3.10 python/example/demo_get_hardware_info.py
```


######### Dead-end approaches — do not use ########
#
# The following two approaches were thoroughly investigated and confirmed not to work.
# They are documented here only to save future effort.
#
# 1. devmem via register 0xC310048:
#    Writes complete without error but have no observable effect on BRS behavior.
#    Example: sudo busybox devmem 0xC310048 32 0x800
#    Result: TDCR reads back as set, but BRS at 5 Mbit/s still fails. Dead end.
#
# 2. Custom DTB + extlinux.conf boot entries (JetsonIO-CAN-TDCR-*):
#    Approach: patch prod_c_can_5m in the device tree DTS, compile to DTB,
#    copy to /boot/dtb/, add LABEL entries to /boot/extlinux/extlinux.conf,
#    switch DEFAULT to e.g. JetsonIO-CAN-TDCR-0800, reboot.
#    Reference: https://forums.developer.nvidia.com/t/canfd-transmission-failure-at-5mbps-on-orin-nx-16gb-module-tdc-offset-issue/367473
#    Result: the boot-time DTB TDCR value does not carry through to runtime
#    interface behavior. Dead end.
#
# The sysfs tdc_offset write is the only confirmed working method.
